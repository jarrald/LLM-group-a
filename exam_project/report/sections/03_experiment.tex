\section{Manual regression versus local LLM prediction}
\subsection{Data inspection and the three approaches}
The direct numerical comparison used the 500-row ice-cream dataset
({\small\path{regression/datasets/ice_cream_regression.csv}}), with \texttt{Temperature} as input and \texttt{Revenue} as target.
In our notebook \path{regression/non-llm.ipynb}, we inspected the rows and data types and plotted temperature against revenue.
The plot showed a roughly linear upward relationship.
We then wrote the regression code ourselves and fitted one final \texttt{LinearRegression} model on 361 training rows.
The notebook reports training, validation, and test metrics and plots predictions for each set; it contains one final successful model configuration.

The data split used two calls to \texttt{train\_test\_split} with \texttt{random\_state=42}.
It first held out 75 test rows (15\%), then took 64 of the remaining 425 rows (15\% of the remainder) for validation, leaving 361 training rows.
The actual train/validation/test shares were 72.2\%/12.8\%/15.0\%.
On all 75 test rows, the manual model achieved $R^2=0.9764$, RMSE $=27.2895$, and MAE $=20.3146$.
Fitting on the training rows gave
\begin{equation}
\widehat{\mathrm{Revenue}}=21.2581\,\mathrm{Temperature}+49.8138.
\end{equation}
To compare the approaches on identical inputs, the evaluation script
\path{regression/compare-predictions.py} rebuilt the same split and fitted model to extract predictions for
three test rows: the coldest, median, and warmest temperatures.
These rows are part of the same 75-row test set.
The script writes the scores to \path{regression/runs/old/predict/results.csv}; the exact prompt and the raw LLM
answers with retrieved rows are stored in \path{regression/runs/old/predict/prompt.md} and
\path{regression/runs/old/predict/report.json}.

The LLM experiment used \model{qwen2.5-coder:7b} through Ollama at temperature 0 with a 4096-token context.
It received the same three test temperatures but no test targets, and it was instructed not to write code, use a calculator, or run a regression.
In the RAG version, 12 reference rows from the training split were indexed with \model{nomic-embed-text}, and the three most similar
rows accompanied each question.
The no-RAG version used the same model and questions without reference rows.

Our process differed from the LLM approach.
We inspected and visualised the data before writing our own regression code.
The LLM was instead asked to solve the prediction task from its instructions and, in the RAG version, retrieved reference information.
We can therefore compare prediction quality, but we should not call one method better merely because its code or workflow looks different.

The manual regression had the lowest MAE: 13.28, compared with 107.15 for LLM+RAG and 368.82 for the LLM without RAG.
RAG therefore lowered the LLM's average error in this run, but the LLM+RAG MAE was still about 8.1 times the manual MAE.
Cases 1--2 of the RAG output exactly match retrieved revenue values, consistent with copying rather than a learned regression rule.
Its third answer (630.00) is far below the actual value, while the no-RAG model's third guess (1000.00) happened to be closer.
These three selected cases show behaviour but are too few to support a broad ranking.
The full 75-row manual MAE (20.31) and the three-case manual MAE (13.28) also use different numbers of test rows and should not be compared directly.

\subsection{Separate controlled code-generation experiment}
This later experiment asked a different question: could smaller local models \emph{generate a runnable regression program} with or without
retrieved documentation?
It did not repeat the direct numerical prediction task.
The two dataset files were \path{regression/datasets/ice_cream_regression.csv} and
\path{regression/datasets/house prices.csv}.
Within each pair, the model, dataset, instruction, 4T fields, temperature (0.2), and context (16,384 tokens) were fixed; only \texttt{top\_k} changed from 0 to 4.
Retrieval used \model{embeddinggemma}; its configuration and chunking are implemented in
\path{regression/rag.py}, using a frozen lean corpus of 566 chunks.
The generated notebooks were executed unchanged with a 60-second timeout by
\path{regression/verify_generated_runs.py}; outputs and execution records are under \path{regression/runs/rag/ui/}.

The manual baseline values above describe prediction accuracy and are not scores for these generated programs.
In the two 1B RAG runs, the model copied a worked example's placeholder \texttt{data.csv} despite an explicit dataset block giving
the real path and forbidding that substitution.
These outcomes concern task completion, not a claim that RAG always harms coding.
