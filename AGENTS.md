# AGENTS.md — Local Multi-LLM Coding Workflow

Instructions for AI coding agents (Cline, Codex, Cursor, Windsurf, …) working in this
repository. **Read this file first.** Cline also loads it automatically as a rules source.

> Language convention: the *code, comments, prompts and README are written in Danish*;
> identifiers, docstrings and technical terms are English. Keep it that way.

---

## 1. What this project is

A local, open-source multi-LLM workflow for the **Mandatory 1** assignment
(*Local Multi-LLM Coding Workflow Evaluation*). A Python/Flask program asks ten
specialised agents to analyse a requirement **in parallel** and produce software
artifacts (architecture, tickets, implementation plan, testing/quality, documentation,
deployment validation, plus four non-functional reviews).

Model backends are **local Ollama** servers. Two model roles are used:

| Role | Default model | Used by agents |
| --- | --- | --- |
| Architect | `qwen2.5-coder:7b` | architecture, tech_lead, implementation |
| Worker / reviewer | `llama3.2:3b` | testing_quality, documentation, deployment, predictability, reproducibility, context_management, security |

The full assignment text is in `docs/Mandatory 1.md` (use the `.md`, **not** the `.pdf`).

---

## 2. Tech stack & prerequisites

- **Python 3.9+** (locally tested on 3.14). Only runtime dependency: `Flask>=3.1,<4`.
- **Ollama** running locally (one or two configurable endpoints) with both models pulled.
- **Windows 11 + PowerShell (`pwsh`)**. All commands below are PowerShell.
- No Node/npm, no bundler — the frontend is inline HTML inside the Python file.

### Known state / gotchas (important)

- Two configurable local endpoints are supported via `ARCHITECT_ENDPOINT` and
  `WORKER_ENDPOINT` (both fall back to `OLLAMA_URL`). Architect-role agents use
  `ARCHITECT_ENDPOINT`; the remaining agents use `WORKER_ENDPOINT`.
- `tests/` now contains real pytest sources (config, workflow, API); run
  `python -m pytest -q`. Static checks: `ruff` (lint/format) and `mypy` (type),
  configured in `pyproject.toml`.

## 4. Setup & run commands (PowerShell)

```powershell
# install dependency
python -m pip install -r requirements.txt

# make sure Ollama has the models
ollama pull qwen2.5-coder:7b
ollama pull llama3.2:3b

# run the workflow from the terminal (interactive prompt if no argument)
python .\model\ollama_workflow.py
python .\model\ollama_workflow.py "Lav en todo-app med login"

# same, but print raw JSON
python .\model\ollama_workflow.py "Lav en todo-app med login" --json

# start the Flask web app -> http://127.0.0.1:5000
python .\model\ollama_workflow.py --web

# agentic mode: agents call tools (write files, run tests) in a sandbox
python .\model\ollama_workflow.py --agentic "Lav en Python-funktion add(a, b) med en pytest-test"          # dry-run: diffs only
python .\model\ollama_workflow.py --agentic --apply "Lav en Python-funktion add(a, b) med en pytest-test"  # write files + run commands
python .\model\ollama_workflow.py --agentic --apply --workspace workspace\demo "Dit krav"
```

### Configuration (environment variables, no code changes needed)

| Variable | Default | Purpose |
| --- | --- | --- |
| `OLLAMA_URL` | `http://localhost:11434` | fallback endpoint for both roles |
| `ARCHITECT_ENDPOINT` | `OLLAMA_URL` | endpoint for architect-role agents |
| `WORKER_ENDPOINT` | `OLLAMA_URL` | endpoint for reviewer/worker agents |
| `ARCHITECT_MODEL` | `qwen2.5-coder:7b` | model for architect-role agents |
| `WORKER_MODEL` | `llama3.2:3b` | model for reviewer/worker agents |
| `MAX_PARALLEL_AGENTS` | `2` | max concurrent Ollama calls (RAM guard) |
| `WORKSPACE_DIR` | `workspace` | sandbox directory for agent file operations |
| `CONTEXT_BUDGET` | `6000` | max chars per artifact handed to the next agent |
| `MAX_AGENT_ROUNDS` | `8` | max tool-calling rounds per agent |

```powershell
$env:ARCHITECT_ENDPOINT = "http://127.0.0.1:11434"
$env:WORKER_ENDPOINT     = "http://127.0.0.1:11435"
$env:ARCHITECT_MODEL     = "qwen2.5-coder:7b"
$env:WORKER_MODEL        = "llama3.2:3b"
python .\model\ollama_workflow.py --web
```

### HTTP API (Flask)

- `GET  /api/health` — verifies Ollama + models; `200` ok, `503` on error.
- `POST /api/workflow` — JSON body `{"requirement": "..."}`; `400` if empty.
  Optional `"mode": "agentic"` and `"apply": true` run the tool-calling pipeline.

## 5. Code conventions

- **Keep the single-file design.** `model/ollama_workflow.py` intentionally holds the
  Flask app, the inline HTML frontend, the `AGENTS` registry and `main()` together.
- **Config via `os.getenv(...)` with defaults** — never hardcode an endpoint or model.
- **Comments and user-facing strings in Danish**; identifiers in English.
- Type hints on functions (the file uses `dict[str, object]`, `list[...]`).
- Standard library first (`urllib.request` is used for Ollama) — avoid new dependencies
  unless the assignment requires it; if you add one, update `requirements.txt`.
- `main()` returns `int` and is guarded by `if __name__ == "__main__":`.
- Agent prompts live in the `AGENTS` dict; the shared framing constants are
  `DEFAULT_TRAITS`, `DEFAULT_TASKS`, `DEFAULT_TONE`, `DEFAULT_TARGETS`.

## 6. Context hygiene — do NOT read these

The repo contains large/generated/binary files that waste tokens. Never read, search or
open them (this is enforced by `.clineignore` and `.clinerules/00-context-hygiene.md`):

- `__pycache__/`, `*.pyc`, `*.pyo`, `*.pyd`
- `.pytest_cache/`, `.mypy_cache/`, `.ruff_cache/`, `.tox/`, `.venv/`, `venv/`
- `workspace/` (generated Ollama run output)
- `*.pdf`, `*.pptx`, `*.docx`, `*.xlsx`, images
- `*.log`

Prefer reading specific files over broad recursive searches, and scope searches to
`model/`, `docs/`, `tests/`.

## 7. Working agreement

**Do**
- Read `README.md`, `plan.md` and this file before making changes.
- Make minimal, focused edits to `model/ollama_workflow.py`.
- Preserve the Danish language convention and the single-file structure.
- Verify your change by running the workflow or the web app (see §4).
- Show the exact command you ran and its result when reporting completion.

**Don't**
- Don't create new frameworks/packages or restructure the project unasked.
- Don't edit or regenerate the PDFs/PPTX in `docs/` and `synopsis_report/`.
- Don't delete `workspace/` runs that are referenced as demo evidence in `plan.md`.
- Don't add dependencies without updating `requirements.txt`.
- Don't read the files listed in §6.
